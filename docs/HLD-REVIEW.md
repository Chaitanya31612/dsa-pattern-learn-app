# HLD completion and app usability review

Reviewed 16 October 2026. Scope: the complete HLD catalog and learning loop, plus the main DSA/LLD pages and representative practice journeys. This is a usability and learning review, not a proof that every existing DSA solution or LLD implementation is correct.

## Delivered course

- Volume 1: 17 preserved modules,72 planned hours.
- Volume 2: 14 new modules,64 planned hours. All thirteen book chapter families plus an original cross-chapter assessment.
- Combined: 31 modules,177 short teaching steps,62 original overview/recap diagrams,95 design/transfer/repair exercises,124 objective questions.
- Four deterministic visual labs: queue overload, concurrent last-seat booking, lost remote reply, and spatial-cell borders.
- New modules each include a small worked teaching example. Practice references and quiz explanations remain hidden until the appropriate submission.

Volume 2 covers nearby places, nearby friends, maps, retained message queues, monitoring/alerts, event aggregation, hotel inventory, email, object storage, leaderboards, payments, wallets, and order matching. The source is `backend/pipeline/hld_volume2.py`; both runtime catalogs are generated by `build_hld_course.py`. Book references use printed page numbers because the supplied scan has irregular PDF offsets. No book PDF or scanned image is bundled.

## Learning review and fixes

The course uses a steady seven-part answer structure with a different dominant risk in each module. Short explanations precede examples, memory cues, and optional depth. Worked teaching examples now reveal one decision at a time and ask for a prediction before later explanations; their Flow step includes the architecture picture. The final lesson step has a whole-design recap diagram. Visual labs require prediction before interaction and an explanation before saving a recall card.

The course map now separates the two volumes and points to an unfinished activity in the selected volume. It distinguishes exposure from practice, an independently reviewed design, and delayed recall. Seven visible evidence checks guide module completion without locking the content or claiming professional certification.

A design submission saves a fixed snapshot; it does not silently start AI. The app explains the separate AI-feedback and reference-reveal buttons. Submission moves focus to feedback. References mark the current draft assisted; a later closed-book attempt can be unaided. Scores remain provisional and an alternative sound design is allowed.

Repairs now use four relevant scoring areas out of 12. Full designs use eight areas out of 24. A focused repair cannot become a full-design pass. Phase time hints scale to exercise duration. The backend validates rubric identity, scores, and readable evidence before saving a report. The UI explains unavailable AI and keeps self-review available.

Lesson-completion recall cards now include actual mechanism explanations. Wrong quiz answers return immediately. Other reviews start after a day, then spread out. Delayed design evidence requires a good self-rating at least seven days after the first design submission; merely seeing an old card does not qualify. Old backups are compatible, and missing historical ratings are not invented.

## Wider app usability findings fixed

- A new LLD session incorrectly reported 100% phase progress from its supplied note templates. Unchanged template lines are now excluded. The UI calls the signal “phases with notes.”
- A LLD launch button could advertise 60 minutes while the session used a stale 50-minute fallback catalog. The framework registers its merged catalog before starting; a new guided parking-lot session was verified at 60:00 and 0% notes progress.
- LLD debriefs now explicitly identify their local heuristic and state that they do not compile or run code. Supplied starter lines do not count as learner-written work in that estimate.
- Settings now names DSA exports/imports and clearing correctly. Counts react after changes. HLD backup remains separate. No real user data was cleared during review.
- The DSA review empty state no longer implies every track is clear while HLD cards are due.
- A DSA catalog failure has a visible retry action. The obsolete unreachable “HLD not live” placeholder was removed.
- Mobile navigation scrolls to the current track. HLD diagrams re-render when the theme changes. Invalid draft diagrams retain their source, show a readable recovery message, and remove temporary Mermaid error elements.
- Volume/activity links retain context. Selecting a practice exercise is reflected in its URL so reload returns to that exercise.

## Practical limits

The full track has 136 planned hours, about 20 weeks at 7 hours/week. A one-month sprint can cover a foundation checkpoint, not the complete two-volume course with delayed evidence.

AI can miss a correctness issue or give imperfect advice. Self-ratings and self-review are also provisional. Validate the key design with a race/failure timeline, meaningful experiment, or another engineer. The labs are intentionally small models, not distributed infrastructure benchmarks. This review did not execute every historical DSA/LLD coding task or wait weeks in real time; delayed scheduling is verified using deterministic time inputs.

Progress remains local to this browser, with export/restore rather than account sync. Live coaching needs a working backend/provider. Build output still warns about the size of some lazy Mermaid chunks; diagrams load on demand. No production deployment, commit, push, or PR was performed.
